# PR差分への変更理由の注釈

## 入力と権限

対象PRのURL（またはホスト・repository・番号）と実行モードを受け取る。
根拠資料や対象範囲の指定は任意。指定があれば差分との対応を確認して使う。
Flowからはメインエージェントが直接実行する。単独実行ではPR差分、コミット、任意の根拠資料を使う。
Flow state、他スキル、HTMLレポートの存在を前提にしない。

下書きでは候補のpath・行・差分の左右・説明・根拠を返す。モード未指定時も下書きにする。
投稿は利用者が行コメントの投稿を明示的に依頼した場合に限る。

## 説明の原則

- 差分だけでは意図が伝わりにくく、レビュー判断に関わる変更を選ぶ。
- 何を変えたかに加え、その変更が必要だった理由と、振る舞い・責務・互換性などへの具体的な影響を記す。
  削除や置換では、元の振る舞いや責務がどう扱われたかを説明する。
- 根拠を確認し、必要に応じて判断記録、成果物の節、コミットなどへの参照を添える。
  記録や差分から確認できない意図は推測で補わない。機密や非公開資料の本文を転記しない。
- 同じ判断を扱う変更は代表する行にまとめる。差分の言い換え、定型的な説明、承認や修正要求は省く。

## 差分への対応と投稿

1. GitHub上の対象PR、base SHA、head SHAと差分を取得する。説明する行が実際の差分にあり、指定された
   変更範囲に属することを確認する。追加・変更後の行には `RIGHT`、削除行には `LEFT` を使う。
   位置を確認できない差分は行コメントから外し、理由を報告する。
2. 投稿直前にbase/headを再取得し、変わった場合は差分から候補を再照合する。
   既存の行コメントを全ページ取得し、自分の投稿済み注釈と照合する。
   注釈には `<!-- flow-pr-annotations: <sha256> -->` を付ける。キーは差分上のpath、side、行、
   対象行の内容、説明の組から計算し、既存のキーまたは現行の差分位置で同じ説明があれば除く。
3. 残った候補を1件の `COMMENT` reviewにまとめる。候補がなければ投稿しない。
   GitHubの [Create a review](https://docs.github.com/en/rest/pulls/reviews#create-a-review-for-a-pull-request) を使い、
   `commit_id` に検証済みhead SHA、`comments` に `path`・`line`・`side`・`body` を指定する。
   `gh api` を使う場合は対象ホストを指定し、投稿本文はJSONファイルを `--input` に渡す。
4. review URLと投稿件数、除外した項目を返す。投稿結果が不明なら既存レビューと行コメントを
   読み直し、反映を確認できるまで再投稿しない。既存コメントの編集・削除やコード変更は行わない。
